# Suricata-Based Network Intrusion Detection and Evaluation

Project for DD2391. We wrote a [Suricata](https://suricata.io/) ruleset (`custom.rules`) that detects common network attacks (SQL injection, XSS, brute force, port scans, DoS/DDoS floods, web shells, vulnerability scanners, ...) and measure how well it works by replaying labelled packet captures through Suricata and comparing the alerts with the ground truth of each dataset.

The report for the assignment is in [`./report.md`](./report.md). This README only explains what the repository contains and how to use it.

## Overview

1. `setup.sh` unpacks the downloaded datasets into `datasets/`, using the file names expected by the scripts.
2. `run.sh` runs Suricata offline on one or more PCAPs with `custom.rules` and writes the alerts to `suricata/`.
3. `evaluate_training.py` / `evaluate_test.py` compare those alerts with the labelled CSV of the same capture and print TP, FN, FP, TN, recall, precision, FPR, TNR, accuracy and F1.

The ruleset is developed on a training set (Edge-IIoTset) and then evaluated on a separate test set (CIC-IDS-2017).

## Repository layout

Files in the repository:
- `report.md`: the report for the assignment.
- `README.md`: this file.
- `custom.rules`: the Suricata ruleset created by us.
- `setup.sh`: extracts, renames and places the downloaded datasets into `datasets/` (`./setup.sh -h` shows what it needs).
- `run.sh`: runs Suricata on one capture and evaluates the result, in training or test mode. (`./run.sh -h` shows how it works).
- `evaluate_training.py`: evaluator for the training set. It matches alerts to CSV records by frame number (`pcap_cnt`), obtained by indexing the PCAP timestamps (needs `dpkt`).
- `evaluate_test.py`: evaluator for the test set. It matches alerts to CICFlowMeter flows by 5-tuple (IPs, ports, protocol), in either direction. No extra dependencies required.

Directories that are not part of the repository (they are not tracked by `.git`):
- `setup/`: created by you before running `setup.sh`. It holds the downloaded files (see setup below).
- `.venv/`: created by you before running `evaluate_training.py`, holds the pip dependecies (e.g. `dpkt`).
- `datasets/`: generated by `setup.sh`. It holds the PCAPs and the ground-truth CSVs used for the rules evaluation.
- `suricata/`: generated by `run.sh`. It holds `eve.json`, `fast.log`, `stats.log` and `suricata.log` of the last run, and is deleted and recreated at every run.

## Requirements
To run this project the following environment is required:
- Linux with `bash` and `sudo` (`run.sh` uses `sudo` for Suricata and to fix the ownership of its output)
- [Suricata](https://suricata.io/) (Tests were run with version 8.0.5)
- `python3` with [`dpkt`](https://pypi.org/project/dpkt/) (used by `evaluate_training.py`):
- `unzip` (used by `setup.sh`)
- Free disk space: for the whole dataset at least 60GB of storage are required.

## Setup (datasets)
The datasets are not in the repository, they are too large to be managed by git and the github infrastructure. Download these files and put them **directly** in a directory called `setup/` in the project root (do not extract the zips):

- `edgeiiotset-cyber-security-dataset-of-iot-iiot.zip`: training PCAPs and CSVs.
  Download: [Kaggle: Edge-IIoTset](https://www.kaggle.com/datasets/mohamedamineferrag/edgeiiotset-cyber-security-dataset-of-iot-iiot/data)
- `CICIDS2017_improved.zip`: test CSVs.
  Download: [CIC-IDS-2017 CSVs](https://intrusion-detection.distrinet-research.be/CNS2022/CICIDS2017.html)
- `Monday-WorkingHours.pcap`, `Tuesday-WorkingHours.pcap`, `Wednesday-workingHours.pcap`, `Thursday-WorkingHours.pcap`, `Friday-WorkingHours.pcap`: test PCAPs.
  Download: [UNB CIC-IDS-2017](https://www.unb.ca/cic/datasets/ids-2017.html), [direct listing](https://cicresearch.ca/CICDataset/CIC-IDS-2017/browse.php?p=CIC-IDS-2017%2FPCAPs)

Then run:

```bash
./setup.sh
```

The script checks that all seven files are present (otherwise it prints what is missing and stops), takes all the CSVs and PCAPs needed, renames everything to the names expected by `run.sh` and places them in `datasets/`. The test PCAPs are hard-linked, so they do not use extra space. After it finishes you can delete `setup/`.

Afterward, `dpkt` needs to be downloaded for the training script using:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install dpkt
```

## Usage
After the environment is properly set up and the datasets are in place, you can run every test from the `run.sh`, which allows a centralized control of datasets and evaluation scripts:
```bash
./run.sh -m 0 -n N     # training: run Suricata on training capture N and evaluate it
./run.sh -m 1 -n N     # test: run Suricata on the test capture N and evaluate it
./run.sh -h            # list all the available indexes
```

Examples:
```bash
./run.sh -m 0 -n 11    # SQL injection
./run.sh -m 1 -n 3     # Wednesday
```

`run.sh` prints the evaluator summary at the end. The Suricata output is kept in `suricata/training/<name>/` or `suricata/test/<day>/`. Be aware that `run.sh` deletes the whole `suricata/` directory at every run, and that the test captures are large, so both Suricata and the evaluator can take a long time on them.

### Running the evaluators by hand

Both evaluators read an existing `eve.json`, so they can be re-run without running Suricata again:

```bash
python3 evaluate_training.py --eve suricata/training/<name>/eve.json --csv datasets/csv/training/<name>.csv --pcap datasets/pcap/training/<name>.pcap
python3 evaluate_test.py --eve suricata/test/<day>/eve.json --csv datasets/csv/test/<day>.csv
```

## The ruleset

`custom.rules` is organised in sections: SQL injection, brute force, vulnerability scanners, web shells, path traversal / enumeration, XSS, port scanning, DoS and reconnaissance, ICMP / SYN / UDP floods, HTTP DDoS, OS fingerprinting and MITM (mDNS).
